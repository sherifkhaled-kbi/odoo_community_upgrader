# Evidence-led improvement opportunities

**Discovery basis:** application `49c16285eb160b11d8a977bba278bf3a3bc333f1` and inspected upstream revisions in [OPENUPGRADE_INTEGRATION.md](OPENUPGRADE_INTEGRATION.md). These are candidate directions, **not an implementation roadmap or approval to change behavior**. Odoo/OpenUpgrade already perform migration script discovery, ordering, and many data transformations; the wrapper should not duplicate them.

| Opportunity | Evidence for need | Expected benefit | Complexity / risk and validation |
| --- | --- | --- | --- |
| Immutable execution manifest | Moving `odoo` tag and OCA branch clone ([core.py:476-493](../../src/odooupgrader/core.py#L476-L493)) | Reproducible diagnosis and controlled upstream updates | Medium; record image digest, clone SHA, library SHA, Python/PG versions, addon hashes; test each supported step |
| Preflight compatibility and data checks | Only source reachability/version checked ([core.py:80-121](../../src/odooupgrader/core.py#L80-L121), [409-427](../../src/odooupgrader/core.py#L409-L427)); UoM ambiguity is detectable | Early actionable rejection without modifying DB | Medium to high; source-specific checks must be versioned, read-only, and tested on sanitized fixtures; avoid one-off customer fixes |
| Per-run isolation | Fixed containers/network/paths and forced removal ([core.py:29-33](../../src/odooupgrader/core.py#L29-L33), [538](../../src/odooupgrader/core.py#L538)) | Prevent cross-run interference and preserve prior output | Medium; Docker naming, volume ownership and cleanup need integration tests |
| Restore and package verification | Ignored restore errors, no artifact/invariant validation ([core.py:363-408](../../src/odooupgrader/core.py#L363-L408), [603-629](../../src/odooupgrader/core.py#L603-L629)) | Reject incomplete migrations | Medium to high; need realistic attachment, module, inventory and accounting fixtures, without claiming generic business correctness |

| Custom/Enterprise module policy | Custom path only at final step ([core.py:469-475](../../src/odooupgrader/core.py#L469-L475)) | Make supported path explicit and avoid silent omission | High; per-version source and licensing, dependencies and migration scripts needed |

`CONFIRMED` OCA already has migration framework patches and a versioned script tree, while official Odoo's `MigrationManager` handles script selection ([framework](https://github.com/OCA/OpenUpgrade/tree/bf12c3cee6097145e53efa589b0d99a7e64d6a87/openupgrade_framework), [Odoo migration.py](https://github.com/odoo/odoo/blob/a5447ae78fa15f25e69ce44fd154bf1d2f1e383a/odoo/modules/migration.py)). New wrapper logic should focus on input readiness, reproducibility, safety, and evidence, and defer data transformation design to versioned migration work when justified. No estimates are offered without approved scope.

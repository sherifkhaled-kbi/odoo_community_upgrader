# OpenUpgrade integration contract

**Basis:** OdooUpgrader `49c16285eb160b11d8a977bba278bf3a3bc333f1`; OpenUpgrade 19.0 branch snapshot [`bf12c3cee6097145e53efa589b0d99a7e64d6a87`](https://github.com/OCA/OpenUpgrade/commit/bf12c3cee6097145e53efa589b0d99a7e64d6a87) on 2026-10-30; 18.0 snapshot [`a393ddbe56b6913eea1e77b42be93152ac00b16d`](https://github.com/OCA/OpenUpgrade/commit/a393ddbe56b6913eea1e77b42be93152ac00b16d); 17.0 snapshot [`61daab09ab6c0d21234b96374d9291d3e02ee9e4`](https://github.com/OCA/OpenUpgrade/commit/61daab09ab6c0d21234b96374d9291d3e02ee9e4). These are **research snapshots, not application pins**. Runtime clone SHAs cannot be inferred without build logs/image provenance.

## Source and execution

`CONFIRMED` For every step the wrapper builds from `odoo:<target_version>`, shallow clones `OCA/OpenUpgrade` at the **moving branch** named by that version, installs that branch's `requirements.txt`, then force-reinstalls `OCA/openupgradelib` at commit [`565d0b33391271a4b2ac27eff8ae19f72fe27d77`](https://github.com/OCA/openupgradelib/commit/565d0b33391271a4b2ac27eff8ae19f72fe27d77) ([core.py:476-493](../../src/odooupgrader/core.py#L476-L493)). [19.0 requirements](https://github.com/OCA/OpenUpgrade/blob/bf12c3cee6097145e53efa589b0d99a7e64d6a87/requirements.txt) names `openupgradelib` without a version; the later reinstall determines the library revision. Image tag, apt packages, pip resolver results, and branch tip are not locked. The `openupgradelib` reinstall uses `--no-deps`, so its transitive requirements rely on the image and preceding install.

`CONFIRMED` The wrapper runs Odoo as a subprocess inside Compose, not by importing OpenUpgrade in host Python. It passes `--upgrade-path=/mnt/extra-addons/openupgrade_scripts/scripts`, `--addons-path=/mnt/extra-addons` (plus custom addons only on the final step), `--update all`, `--stop-after-init`, and `--load=base,web,openupgrade_framework` (plus custom module names on the final step) ([core.py:502-535](../../src/odooupgrader/core.py#L502-L535)). There is no wrapper option for another upgrade path or OpenUpgrade revision. Extra addons are copied and pip dependencies installed at every step, but modules are only added to `addons-path`/`--load` on the final step ([core.py:456-475](../../src/odooupgrader/core.py#L456-L475)). The wrapper never patches upstream files.

## Framework mechanics inspected

`CONFIRMED` [OpenUpgrade framework `__init__.py`](https://github.com/OCA/OpenUpgrade/blob/bf12c3cee6097145e53efa589b0d99a7e64d6a87/openupgrade_framework/__init__.py#L1-L16) imports Odoo patches and auto-populates `upgrade_path` only if absent; the wrapper explicitly passes a path. The framework [loading patch](https://github.com/OCA/OpenUpgrade/blob/bf12c3cee6097145e53efa589b0d99a7e64d6a87/openupgrade_framework/odoo_patch/odoo/modules/loading.py) forces pre scripts for newly installed dependencies. Its [migration patch](https://github.com/OCA/OpenUpgrade/blob/bf12c3cee6097145e53efa589b0d99a7e64d6a87/openupgrade_framework/odoo_patch/odoo/modules/migration.py) filters one conflicting Odoo script. Its [module graph patch](https://github.com/OCA/OpenUpgrade/blob/bf12c3cee6097145e53efa589b0d99a7e64d6a87/openupgrade_framework/odoo_patch/odoo/modules/module_graph.py) changes demo/field behavior. Its [model patch](https://github.com/OCA/OpenUpgrade/blob/bf12c3cee6097145e53efa589b0d99a7e64d6a87/openupgrade_framework/odoo_patch/odoo/orm/models.py) changes obsolete-record deletion handling. These patches make the official Odoo image plus OCA addons the migration runtime; OpenUpgrade has no separate `odoo/` source directory in this inspected 19.0 root.

`CONFIRMED` Official [Odoo 19 `MigrationManager._get_files` and `migrate_module`](https://github.com/odoo/odoo/blob/a5447ae78fa15f25e69ce44fd154bf1d2f1e383a/odoo/modules/migration.py) discover per-module directories from `odoo.upgrade.__path__`, validate version folders, select scripts between installed and current module versions, and run `pre-`, `post-`, and `end-` files in sorted order. `exec_script` imports `migrate` and calls it with the installed version. OCA's [decorator at pinned library lines 2607-2685](https://github.com/OCA/openupgradelib/blob/565d0b33391271a4b2ac27eff8ae19f72fe27d77/openupgradelib/openupgrade.py#L2607-L2685) supplies an Odoo environment, savepoint, and logging. The framework, Odoo, and library all participate; the wrapper does not call individual scripts.
